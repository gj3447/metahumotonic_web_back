# metahumotonic_web_back의 역할

2026-09-27 사용자 정정: **MetaHumotonic의 대표 웹사이트를 위한 백엔드가 우선이다.**
사람이 회사와 철학을 이해하고 제품·연구·글·영상·코드로 이어지는 경험을 제공한다.
회사 공통 프로그램·KG·MCP·서버 연결은 그 위에 확장하는 능력이다.

## 웹사이트와의 관계

| 방문자의 목적 | 웹에서 보여줄 것 | 백엔드의 역할 |
|---|---|---|
| 어떤 회사인지 이해 | 회사 소개, 사명과 원칙, 철학 | 공개 콘텐츠와 출처의 일관성 유지 |
| 무엇을 만드는지 발견 | 수풀림·버엑시·메이플리니지 등 제품 소개 | 소개·상태·안전한 공식 링크·관련 콘텐츠 제공 |
| 연구를 이해 | HSWM·USL·HSPINE·LakatoTree 소개와 연구 기록 | 공개 가능한 연구 자료 검색·연결 |
| 더 배우기 | Wiki·Book·읽기 지도·GitHub·YouTube | 공개 자료의 의미 관계와 게시 이력 관리 |
| 참여하기 | 피드백, 커뮤니티 Wiki | 저장·검토·권한·수정 이력 처리 |
| 도구와 연결 | 별도 개발자/운영 기능 | 인증된 KG/USL/MCP 연결, 서비스 등록·관측 |

회사 웹사이트의 홈이 내부 관리 콘솔 역할까지 맡을 필요는 없다. 웹에는 방문자의
질문에 답하는 공개 투영을 제공하고, 서버와 데이터베이스의 주소·상태·접속 권한은
기존 내부 접근 경계에서 다룬다. 각 게임·제품은 고유한 실행 서버와 데이터를 소유한다.

## 현재 구현과 다음 도입 기준

**현재 프런트엔드**는 Astro 정적 회사 홈, 9개 공개 프로젝트의 검색·상세, 51개 노드와
79개 관계의 학습 그래프, Wiki/Book, 검토된 GitHub·YouTube 링크를 제공한다.
홈·프로젝트·학습 콘텐츠는 빌드 시 편집본으로 게시된다. 런타임 KG 또는 내부 자산
목록을 방문자 브라우저에 직접 보내지 않는다. 이번 변경은 홈·프로젝트·공통 레이아웃의
시각/정보 구조를 회사 소개 중심으로 정리했고, 후속 사도·공리·Agent 페이지와 함께
정적 웹을 2026-09-27에 실제 배포했다. 상세 증거는 프런트엔드의
`docs/SEMANTIC_COMPANY_WEBSITE_2026-09-27.md`에 있다.

**현재 백엔드**는 TS + Effect HTTP/MCP 진입점, 피드백 Mongo 저장, Redis 제한,
공개 연구 API, 기존 Python Wiki/ontology 연결, 인증된 회사 프로그램 그래프와
선택적 PostgreSQL 자산 버전·관측 저장을 구현한다. 이 기능들을 공개 웹에서 모두
사용하고 있다는 뜻은 아니다. 운영 전환 여부는 각 배포 증거로 별도 판단한다.

추가 도입은 웹에서 실제 필요한 순서로 진행한다:

1. 콘텐츠 종류(제품·연구·글·영상), 게시 상태, 공식 링크와 연관 자료의 계약을 통일한다.
   편집자용 게시 흐름이 필요해지면 PostgreSQL의 초안/리비전/게시 버전으로 확장한다.
   현재 Git 편집본을 바로 없애거나 CMS 서버를 설치할 필요는 없다.
2. 공개된 콘텐츠를 통합 검색한다. 정적 자료는 기존 Pagefind를 활용하고,
   동적 자료의 양과 갱신 요구가 커지면 PostgreSQL 검색을 검토한다.
3. 기존 피드백·Wiki 참여 흐름을 회사 웹의 필요 지점과 연결한다.
   별도 회원 기능은 저장·구독·협업 등 실제 사용 사례가 생길 때 추가한다.
4. KG/USL 관계를 ‘관련 제품·연구·글·영상’ 탐색에 사용한다. JSON-LD와 의미 있는
   안정된 ID를 유지하고 공개 투영의 출처·버전·검증을 함께 관리한다.
5. MCP·서버 등록은 개발자와 내부 운영의 확장으로 유지한다.

기술 중심은 **Astro + TypeScript 웹 / TypeScript + Effect API / PostgreSQL의
트랜잭션 데이터 / 기존 Neo4j 의미 관계**다. 이미 사용하는 Mongo·Redis·Wiki 저장소는
소유 기능과 함께 유지한다. 위의 콘텐츠 CMS·통합 검색·회원 기능은 도입 기준과
후속 방향이며, 이번에 새로 완성했다고 주장하지 않는다.

회사 플랫폼의 기존 구현 상세는 [COMPANY_BACKEND.md](COMPANY_BACKEND.md),
[COMPANY_PLATFORM_ARCHITECTURE.md](COMPANY_PLATFORM_ARCHITECTURE.md),
[PLATFORM_POSTGRES.md](PLATFORM_POSTGRES.md)를 따른다. 이 문서는 그 기능의
우선순위와 웹사이트를 위한 목적을 명확히 한다.
