# Metahumotonic ontology facade

This service exposes one conflict-aware, sanitized ontology release as a
read-only internal API. It is not a raw KG proxy and never falls back to live
Neo4j.

## Authority and publication boundary

- Schema: `metahumotonic-public-graph/v1`
- Release: `metahumotonic-public-graph-v1-2026-08-30`
- Release state: `ACTIVE_INTERNAL_CONFLICT_AWARE`
- Publication status: `INTERNAL_ONLY`
- Authentication: independent `X-Ontology-Key`; KG read/write keys are not accepted

The snapshot itself is not committed to this repository. An operator mounts the
browser-view JSON generated by the SYMPOSIUM sanitizer as a read-only file and
pins two different digests:

1. `MHB_ONTOLOGY_SNAPSHOT_SHA256` is SHA-256 over the exact mounted JSON bytes.
2. `MHB_ONTOLOGY_CONTENT_SHA256` is the canonical source-manifest content digest
   carried in `meta.content_sha256`. It is a provenance binding, not a second
   digest recomputed over the browser JSON.

Startup rejects an absent file, either digest mismatch, unexpected DTO field,
private marker, wrong collection cardinality, or broken graph topology. There is
no raw-record fallback.

## Required runtime configuration

```dotenv
MHB_ONTOLOGY_ENABLED=true
MHB_ONTOLOGY_SNAPSHOT_PATH=/run/metahumotonic/ontology/browser-view.json
MHB_ONTOLOGY_SNAPSHOT_SHA256=<64 lowercase hex>
MHB_ONTOLOGY_CONTENT_SHA256=<64 lowercase hex>
MHB_ONTOLOGY_INTERNAL_KEY=<independent random value, at least 32 bytes>
```

When disabled, ontology endpoints return `503`. When enabled with an invalid
configuration, application startup fails. `/ready` reports
`ontology_required=true` and is `503` whenever the required runtime is not live.

## API contract

All success responses use this envelope:

```json
{
  "data": {},
  "meta": {
    "schema_version": "metahumotonic-public-graph/v1",
    "projection_id": "metahumotonic-public-graph-v1-2026-08-30",
    "release_state": "ACTIVE_INTERNAL_CONFLICT_AWARE",
    "publication_status": "INTERNAL_ONLY",
    "content_sha256": "..."
  },
  "page": { "next_cursor": null }
}
```

`page` appears only on paginated endpoints. Errors use:

```json
{
  "error": {
    "code": "ONTOLOGY_BAD_REQUEST",
    "message": "...",
    "request_id": "server-generated-id",
    "details": {}
  },
  "meta": {
    "schema_version": "metahumotonic-public-graph/v1",
    "projection_id": "metahumotonic-public-graph-v1-2026-08-30"
  }
}
```

Endpoints:

- `GET /api/v1/ontology/search?q=&kind=&limit=&cursor=`
- `GET /api/v1/ontology/conflicts?subject_public_id=&severity=&status=&limit=&cursor=`
- `GET /api/v1/ontology/nodes/{public_id}`
- `GET /api/v1/ontology/nodes/{public_id}/neighbors?direction=&predicate=&limit=&cursor=`
- `GET /api/v1/ontology/schema`
- `GET /api/v1/ontology/releases/{projection_id}`

Search uses NFKC/casefold matching over canonical names and approved aliases,
ranked exact → prefix → substring with opaque `public_id` as the tie-breaker.
The historical `OM` abbreviation does not resolve the OMC entity; `OMC` does.
Opaque cursors are HMAC-signed and bound to source content digest, endpoint,
filters, limit, and offset. Tampered, stale, or cross-query cursors return `400`.
Conflict filters use exact uppercase ontology tokens and an opaque
`subject_public_id`; scope-only conflicts remain visible in the unfiltered index
but are never falsely attached to a public node.

Every successful representation has a route/parameter-specific strong ETag and
`Cache-Control: private`. The immutable release is private-cacheable for one
year. Errors are `private, no-store`.

## Canonical invariants enforced at startup

- 12 axioms, 12 apostle positions, 7 legion commanders, 6 OMC commanders,
  2 phases, 4 structural patterns, 15 relations, and 8 contained conflicts.
- Apostle slot 8 is 입체운행구름; `OMC` is the current abbreviation and `OM`
  is not an alias.
- Apostle positions other than 9 are exactly `SELECTED`, contain an entity, and
  cannot carry candidates. Slot 9 has `entity=null`, `CONFLICT_PENDING`, exactly
  two uniquely identified Jesus/Aten candidates, and no default-served
  candidate. Its node endpoint returns `409`.
- Harness/Hades is one commander entity and one slot.
- The OMC roster is exactly `333`, `CHU`, `CRL`, `engineboy`, `orrr`, `HSWM`.
  HSWM is an identity/scope record, not evidence that its separate implementation
  repository is complete.
- Relationship topology is exactly apostle 4 → seven legion commanders,
  OMC → six direct commanders, and the two phases → apostle 10.

## Verification and deployment boundary

```sh
uv run --extra dev pytest -q
```

For a local real-snapshot smoke test, generate the browser view in SYMPOSIUM,
calculate its exact byte digest, set the five environment variables above, and
run `uv run uvicorn app.main:app`. Keep the snapshot and key out of Git.

The implementation does not open production ingress. The current ontology
release is `INTERNAL_ONLY`; adding a public Nginx/Traefik route, mounting the
snapshot on both VM100 replicas, or using the browser shell on a shared public
origin requires a separate publication and operations decision. In particular,
never bake `X-Ontology-Key` into frontend code or a release artifact.
